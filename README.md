# Fap Instructor Personal

A GitHub-ready, self-hosted Docker app for the core website-style functionality: **scripts, script builder, player, metronome, procedural game generators, media, device hooks, challenger rooms, and admin tools**.

This personal edition intentionally has:

- **no age gate**
- **no payments**
- **no subscriptions**
- **no Patreon flow**
- **no paywalls**

Everything runs from a single container with a local SQLite database volume.

---

## Features

### Scripts and builder

- Browse/search scripts by title, description, and tags
- Vote and track play counts
- Create/edit scripts in a structured JSON event builder
- Reorder, duplicate, import, export, and validate events
- Preview draft scripts before saving
- Export scripts as FunScript-compatible JSON

### Player

- Event queue playback
- Countdown timers and total progress
- Visual metronome with optional audio click
- Browser text-to-speech for instructor messages
- Interactive instruction choices that can enqueue more events
- Media cues for video, audio, images, and embeds
- Optional automatic device cue sending

### Game generators

- Configurable procedural sessions
- Tempo range, duration, intensity, outcome, check-ins, and edge markers
- Saved generated games with replay support

### Media

- Add remote media URLs
- Upload local video/audio/images
- Persist uploads in the Docker volume

### Devices

Default mode is safe mock mode: commands are simulated and logged.

Optional real integration hooks are included for:

- The Handy
- Lovense Basic API
- Autoblow-compatible custom endpoints

### Challenger rooms

- Create/join WebSocket rooms
- Presence snapshots
- Room chat
- Shared state/event broadcast

### Admin

- User list and local role management
- Database object counts
- Audit log
- Live challenger room diagnostics
- Queue-status-compatible placeholder endpoints

## Quick start: local Docker build

```bash
git clone https://github.com/YOUR-GITHUB-USER/fapinstructor-personal.git
cd fapinstructor-personal
cp .env.example .env
# Edit .env, especially SEED_ADMIN_PASSWORD
docker compose up --build
```

Open:

```text
http://localhost:8080
```

Default seeded login, unless changed in `.env`:

```text
admin@example.com
admin123!
```

## Deploy with GitHub Container Registry

This repository includes a GitHub Actions workflow that builds and publishes a Docker image to **GHCR** on pushes to `main` and version tags.

### 1. Push to GitHub

```bash
git init
git add .
git commit -m "Initial personal Docker app"
git branch -M main
git remote add origin https://github.com/YOUR-GITHUB-USER/fapinstructor-personal.git
git push -u origin main
```

GitHub Actions will publish:

```text
ghcr.io/YOUR-GITHUB-USER/fapinstructor-personal:latest
```

If your GitHub username or repository has capital letters, GHCR will still use the lowercase image path generated by the workflow.

### 2. Deploy the published image on your server

Copy these files to the server:

```text
docker-compose.prod.yml
.env.example
```

Create your env file:

```bash
cp .env.example .env
nano .env
```

Start the image:

```bash
IMAGE=ghcr.io/YOUR-GITHUB-USER/fapinstructor-personal:latest \
  docker compose -f docker-compose.prod.yml up -d
```

Update later:

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

## Configuration

`.env.example` contains the runtime configuration:

| Variable | Purpose |
|---|---|
| `APP_NAME` | Display name in the UI |
| `PUBLIC_BASE_URL` | Base URL used by the app |
| `DATA_DIR` | Container data path, normally `/data` |
| `ALLOW_REGISTRATION` | Enable/disable local signups |
| `SEED_DEMO_DATA` | Seed demo scripts/generators on first run |
| `SEED_ADMIN_EMAIL` | Initial admin email |
| `SEED_ADMIN_PASSWORD` | Initial admin password — change it |
| `SECURE_COOKIES` | Set `true` when serving through HTTPS |
| `ENABLE_REMOTE_INTEGRATIONS` | `false` = simulate device calls; `true` = call configured device APIs |
| `HANDY_API_BASE` | The Handy API base URL |
| `HANDY_SCRIPT_API` | The Handy script API URL |
| `LOVENSE_API_TOKEN` | Lovense Basic API token, if used |
| `LOVENSE_BASIC_API` | Lovense Basic API base URL |
| `AUTOBLOW_LATENCY_URL` | Autoblow connectivity/test endpoint |
| `LANGUAGETOOL_API` | Optional LanguageTool-compatible server |

## Data persistence

Data lives in the Docker volume mounted at `/data`:

```text
/data/app.db
/data/uploads/*
```

Reset all local data:

```bash
docker compose down -v
```

Back up the SQLite database and uploads:

```bash
docker run --rm -v fapinstructor-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/fapinstructor-backup.tgz /data
```

```text
http://localhost:8080
```

```text
http://localhost:8080/docs
```

## Notes

- This is designed for personal/self-hosted use.
- Do not commit `.env`; it is intentionally ignored.
- Device credentials, if added, are stored in your local SQLite database as JSON config.
- Remote device integrations should be tested carefully with your own devices before enabling `ENABLE_REMOTE_INTEGRATIONS=true`.
